# Automatic promotion requires accepted responsibility and enablement

Automatic owner promotion requires the owner's own explicit commitment or unambiguous acceptance
of the particular obligation as sole performer, supported by the current responsibility contract
and all existing eligibility guards. Another speaker's assignment without that acceptance remains
for review. This accepts additional review to prevent a grounded name from becoming unauthorized
accepted work, as settled in
[Define supported responsibility and automatic promotion](https://github.com/nicolas-found42/chief-of-staff-demo/issues/343#issuecomment-5623947689).

Passing the dedicated fixtures and live-output audit makes explicit enablement available; it does
not resume an earlier enabled preference. Enablement applies only to future eligible first
extractions, with no backlog sweep or reconsideration of historical review-only outcomes. Recovery
preserves an already accepted Task and its original operation rather than making a new decision.

This refines ADR-0057 while preserving default stage-all, owner-only and first-extraction-only
promotion, duplicate guards, open Tasks and independent destination authorization. ADRs 0080–0082
continue to govern identity, accepted work, deletion and immutable context. These are accepted
specifications awaiting implementation and validation; no live policy setting was changed.
